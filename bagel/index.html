BAGEL 架构图解

一句话：BAGEL 是一个 Qwen2.5-7B 语言模型，里面每一层的权重都备了两套。一套管“看懂”（文本和 ViT 图像 token），一套管“画出来”（VAE 图像 token）。两套权重各算各的 token，但在同一次自注意力里互相看得见。

1. 整体：三种 token 进同一条序列

图像会以两种身份进入模型。要让模型看懂它，就走 SigLIP2 ViT，得到语义 token。要让模型生成或修改它，就走 FLUX VAE，得到像素级的 latent token。两种 token 和文本 token 交错排在一条序列里。

输出也分两头：文本位置接语言模型头，预测下一个词；VAE 位置接一个线性层，预测流匹配的速度场，采样后用 VAE 解码成图。

2. 一层里面：两套权重，一次注意力

这就是 MoT（Mixture-of-Transformers）。每个 token 只走自己那一套的 Norm、Q/K/V 投影、输出投影和 MLP。唯一把两边连起来的是中间那次自注意力：两套投影算出的 Q、K、V 按原位置拼回一条序列，一起做注意力。

所以生成专家能直接读到理解专家每一层的中间结果，反过来也一样，中间没有额外的瓶颈层。生成这套权重初始化时就是理解那套的拷贝。

3. 谁能看见谁：注意力掩码

三条规则叠在一起：

  • 默认是因果的：每个 token 只能看它前面的。
  • 同一张图内部是全连接的：图里的 token 互相都能看见，不分先后。
  • 正在去噪的那张图是“隐身”的：只有它自己的 token 能看见它，后面的任何 token 都看不见。

第三条的后果是：一张图生成完之后，要把它的干净 VAE token 和 ViT token 再接到序列后面，后续内容才能引用它。
